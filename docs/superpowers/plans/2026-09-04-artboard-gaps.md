Good for one-way communication like town halls." with one select "Your interpretation language"; footer "Learn more" link left, "Cancel" and primary "Turn on" right. Files: `src/sidepanel.html`, `src/sidepanel.css`, `src/sidepanel.js`, `src/offscreen.js`, `src/lib/i18n.js` (main I18N: add every key to `en`, `zh` and `id`; the other locales spread `...en`), new `src/lib/lang-detect.js`, new `test/lang-detect.test.mjs`, `docs/NOTES-V2-STATUS.md` (short "Interpreter mode" section), `CHANGELOG.md` (Unreleased entry).

Existing behaviour is exactly `simultaneous` (one-way `srcLang → tgtLang`), so nothing changes for existing users.
2. **Entry point.** In the Captions view, directly under the Task Mode row, a full-width pill row `Interpreter mode · <summary>` with a `Change` button (`id="btn-interpreter"`), where summary is `One-way · JA → EN` or `Two-way · ZH ⇄ EN`. 3. **Consecutive mode = two-way.** When `mode === 'consecutive'`: the From/To selects are hidden and replaced by the summary row (they still hold `a`/`b` internally); the task is forced to `+ Translate`; `updateWarning()`/model checks require BOTH translation pairs `a→b` and `b→a` (list each missing pair with its own Download button, reusing the existing per-pair download UI); the realtime config sent to `offscreen.js` carries `interpreter: { mode: 'consecutive', a, b }`.
4. **Per-utterance direction in the pipeline (`src/offscreen.js`).** In consecutive mode each finalised utterance is transcribed with `language: 'auto'`, then `detectLanguage(text, [a, b])` from `src/lib/lang-detect.js` decides which of the two languages was spoken; the utterance is translated INTO the other one (`src = detected, tgt = other`) through the existing translate path, and every emitted caption line carries `dir: { src, tgt }`. When the ASR engine reports a language (native helper or a future engine field), prefer it over the heuristic — plumb an optional `language` field through `transcribe()`'s return shape ONLY if the engine provides it; do not fabricate one. Simultaneous mode is byte-for-byte the current path.
5. **`src/lib/lang-detect.js`.** Pure function `detectLanguage(text, candidates)` → one of `candidates`. Rules, in order: script detection (Han → zh, Hiragana/Katakana → ja, Hangul → ko, Cyrillic → ru|uk (prefer whichever is a candidate; if both, 'ї/є/ґ' present → uk), Arabic → ar, Thai → th, Devanagari → hi); if the script identifies exactly one candidate, return it; otherwise for Latin-script candidates score each by stop-word hits from small built-in lists (en, id, de, fr, es, it, nl, pl, vi, pt, tr — ≥25 words each, lowercase, diacritics kept) and return the best; ties or no hits → `candidates[0]`. Export the lists for tests. No network, no models.
